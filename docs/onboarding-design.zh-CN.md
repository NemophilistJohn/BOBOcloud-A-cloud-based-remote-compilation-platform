# 新手指引设计提案

[English](onboarding-design.en.md) · 本文是设计提案，尚未实现。

## 目标与现有基础

让第一次使用的人完成一个真实闭环：打开项目、选择运行环境、运行代码、看到结果，知道出错时去哪里处理。无需先理解 Docker、LSP、缓存代次或插件架构。

当前架构足够支持第一版，无需改造 Go 服务端。`client/src/settings.ts` 已有 `openFirstRun()`，`client/src/app.js` 已处理首次连接和仅本地使用；但它们主要解决服务器配置，没有覆盖首次成功运行。私有 renderer 服务注册表已经提供 settings、serverCapabilities、cloudFeaturePolicy、workspaceLaunch、runtime、runOutput 等能力。

## 页面与交互

使用普通工作台“开始使用”页签，首次启动自动打开，帮助菜单可再次打开。保留原有首次连接入口，但由新页面串联它；设置弹窗仍负责编辑配置，指引不复制配置表单。Cloud Forge 主题沿用现有主题变量，其他主题也必须适配。

```text
开始使用                                      [稍后再说]
你想先做什么？   [连接云端运行] [先打开本地项目]

首次云端运行                              已完成 2 / 5
✓ 连接服务器        已验证安全连接             [连接设置]
✓ 登录账号          当前账号可用               [账号]
→ 打开项目          打开自己的项目或创建示例     [打开] [创建示例]
○ 选择运行环境      将按文件类型推荐             [环境中心]
○ 运行并查看结果    完成一次成功运行             [运行]

遇到问题？ [连接诊断] [查看指南]
接下来可以尝试：代码补全 · 项目依赖 · 调试 · 团队协作
```

- 每步显示“为什么需要”“当前状态”和一个主操作；首次成功运行是核心终点，LSP、终端、依赖、调试放在后续体验区，不增加必做项。
- 本地路径只要求打开目录并体验编辑，不把云端登录标成失败；云端运行按实际能力引导连接。自行部署服务器是文档入口，不在引导中执行部署。
- 示例创建需用户选择目录并确认；只写入新目录，不覆盖现有文件。优先提供无需第三方包的 Python 示例，只有服务端支持时才推荐该环境，否则提供可用语言示例。
- 运行环境来自当前服务器真实清单，推荐项不等于已安装、可启动；环境不可用时给出原因和下一步。
- 可选轻量气泡锚定运行按钮、输出面板等稳定语义位置；不抢焦点，不遮挡编辑区，没有目标时回到指引卡片。切换项目、弹窗打开或运行中暂停气泡。
- 用户可跳过、恢复或重置指引。升级不强制重复已完成教程；功能更新提示与首次引导分开。

## 连接诊断

不要将所有失败合并成“连接失败”。分别展示 HTTP 服务、WebSocket 安全握手、账号授权、运行环境以及需要时的 SSH/SFTP 状态。已配置不等于已验证；不支持、未检测和失败应分开。

本次终端错误就是应当明确呈现的场景：实际使用 WSS，但旧调用方给证书校验传入了 HTTPS 地址。修复后应继续校验实际连接地址，绝不能通过关闭证书验证完成引导。指纹不匹配时提供“查看证书详情 / 修改连接配置”，不能自动信任新证书。诊断请求按需触发、可取消，不为展示进度启动临时容器、终端或 LSP。

## 服务设计

新增私有 `workbench.onboarding` 服务，职责是状态归约、推荐下一步、进度提示；视图只渲染，操作通过现有命令或窄接口执行。它不持有账号凭据，不直接请求网络、不执行 shell，不向插件暴露主进程权限。

```mermaid
flowchart LR
  View[开始使用页 / 可选气泡] --> Guide[workbench.onboarding]
  Guide --> Commands[现有命令和设置入口]
  State[能力 / 账号 / 项目 / 环境 / 运行状态适配器] --> Guide
  Commands --> Owners[现有服务及主进程权限边界]
  Owners --> State
```

现有接口并不都支持订阅：serverCapabilities 已有订阅；workspaceLaunch 的 host 有 `onDidOpen`，但不能据此假设它覆盖所有关闭与切换；runOutput 目前是输出操作 facade，没有统一运行完成订阅。实施时应在工作区生命周期和运行协调者补充只读快照及语义事件，再由适配器注入指引；不能通过轮询 DOM、解析输出文本或散读 `window.BOBO` 判定成功。`runOutput.finish` 仅是显示接口，成功依据应来自权威运行结果。

建议事件：连接状态改变、授权状态改变、工作区激活/清空、运行环境改变、运行完成。事件包含服务器身份、账号身份、workspace revision 与 operation id；订阅可释放，异步探测可取消，迟到结果不得更新新上下文。尚不存在的事件属于实施工作，不应在文档中描述为已有能力。

步骤状态为 `pending / checking / ready / blocked / skipped`；只有真实结果才能进入 ready。历史“完成过一次运行”与当前“环境就绪”分别记录：换服务器、退出账号或换项目后重新计算当前就绪状态，历史徽章不冒充当前健康状态。

只持久化教程版本、已跳过提示及带上下文标识的完成提示；不保存 token、API Key、源代码或终端输出。启动时从当前快照重新计算。停止指引只释放它自己的订阅和探测，不终止用户的运行、同步、调试或语言服务。切换项目调用现有生命周期策略，不由教程自行取消业务任务。

## 实施顺序与验收

1. 补齐最小状态与事件适配器，实现状态机和上下文隔离。
2. 增加开始使用页与连接诊断，复用现有设置、登录、打开项目和运行入口；同时补齐中文、英文、日文文案及键盘/读屏支持。
3. 加入安全示例项目创建，再逐步增加可跳过的上下文气泡。

用全新用户配置验证无服务器、本地编辑、有效私有证书、错误指纹、授权过期、无可用环境、运行失败后恢复、项目切换时探测迟到、退出重进以及切换语言。首次运行成功必须基于本轮当前项目的运行结果，不能点击“下一步”即完成。已有项目用户升级后不应被强制中断。

成功标准是能独立完成首次运行、能理解失败原因、能随时退出和恢复；不把增加弹窗数当作引导覆盖率。
