# LSP 连接与本地缓存基线

## 2026-10-04 故障与证据

本机实际服务器配置为 `81.70.51.43`，TLS 开启，WebSocket 端口为 3101，已配置证书指纹。
在 Electron 主进程中直接使用全局 `WebSocket`，连接 `wss://81.70.51.43:3101/lsp`，可稳定复现 `Received network error or non-101 status code`。
相同地址通过 Node `ws` 连接，在发送凭据前验证已配置的 SHA-256 指纹，TLS 和 WebSocket 升级成功。
Electron 的 Chromium `setCertificateVerifyProc` 没有覆盖主进程全局 WebSocket 的 Node 网络路径。
此前只修改端口和服务端代码不能解决这个客户端 TLS 问题；原界面测试替换了全局 WebSocket，也没有覆盖真实证书握手。

修复后，真实 Electron 对云端 `tryjava` 的 Python 3.10 分析完成初始化，依赖状态为 `ready`；`import numpy as np` 后 `np.` 返回 660 个候选，包含 `array`。
这是一次实际环境验证结果，不是所有负载下的延迟或吞吐保证。

进一步在真实科学计算依赖目录验证发现：库索引扫描耗尽 1.5 秒预算后，最终整理继续沿用已耗尽的预算，丢弃已采集模块，产生成功但空且 `truncated` 的索引。受保护目录可正常读取，问题不在目录权限或挂载保护。
服务端修复为扫描和整理分别设置 1.5 秒、250 毫秒上限，保留原有数量/解析步骤限额；先收集顶层 Python 包，再深入子模块。内部磁盘索引文件版本升级，避免旧空索引阻止重建；对外协议保持不变。
部署后清除该代次的旧生成索引，真实目录重新构建并返回两页、1509 个模块的部分索引，其中包含 `numpy` 与 `array`。模块数受扫描预算影响，不是完整性承诺。`truncated` 表明预算内覆盖不完整，不能宣称缓存了全部依赖；有效的已扫描部分以明确的覆盖标记保存在本机，同样按依赖代次隔离，界面显示“部分覆盖”，避免每次打开项目都重新下载。

## 必须保持的连接行为

- 主进程管理连接与凭据；renderer 不接触证书或 TLS 配置权限。
- LSP 使用专用 WebSocket 端口。HTTPS 地址转换为 WSS，不能降级为 WS。
- 无指纹的 WSS 使用正常 CA 校验。私有证书只能通过已配置指纹授权；先校验实际对端证书，再读取和发送凭据。
- 错误指纹、不受信任证书、明确的永久 HTTP 升级拒绝和鉴权失败应停止自动重试，保留错误原因。修正配置或显式重启后才恢复。
- 临时网络中断保留退避重连；重连后重新初始化并同步文档。旧连接、旧身份的回调不能写入新上下文。
- 不要用 `NODE_TLS_REJECT_UNAUTHORIZED=0`、无条件关闭 TLS 检查或绕过身份校验修复连通性。

## 缓存策略与边界

补全协调层统一合并本地规则、当前文档、学习偏好、库摘要和远端分析器结果。先排序再截断，远端结果保留原有编辑和解析元数据。摘要只提供公开名称，不代替类型推断、定义跳转或引用图。

设置页分为三种策略，另行控制是否持久化到磁盘：

| 策略 | 行为 |
| --- | --- |
| 按需 | 先获取可导入名称目录，只在需要某个模块时读取其公开 API。 |
| 智能（默认） | 在按需基础上，空闲时预热当前文件已导入的模块。 |
| 项目 | 空闲时逐页扫描当前项目依赖并预热模块及子模块摘要，直到完成或达到明确的覆盖上限。 |

后台任务串行推进，在输入、运行、调试、同步和工作区变化时让路。前台模块请求优先于后续后台页；已执行的短探测受超时约束。资源限流、探测失败保留已取得的页面并退避重试，不持久化失败造成的空目录。项目模式的完成表示预算内摘要遍历完成，不是完整语义分析。

后台摘要和磁盘恢复不会反复重开或重排当前已有内容的补全框。每个精确输入上下文只允许空列表在首个匹配结果到达时更新一次；当前语义请求的首个响应可在用户尚未交互时合并新增的匹配候选。方向键、鼠标选择、确认和 Escape 会锁住当前上下文。后续输入或手动调用补全自然采用最新缓存与学习排序。

服务端支持 `catalog`、`module`、`project` 三种查询；旧客户端仍可使用原 Python 索引协议。目录与 API 解析分离，Go、Rust、Java 和头文件目录采用有界渐进发现。Python/Node 还从所选运行时的不可变镜像读取内置库目录，避免把 LSP 工具镜像中的包误认作运行环境中的包。探测不执行第三方包，不挂载工作区、不联网，进入维护资源准入并在容器清理后释放租约。

| 语言 | 摘要覆盖 |
| --- | --- |
| Python | 安装包及标准库目录、静态声明、别名和有限重导出。动态生成及二进制扩展的成员继续由远端分析器提供。 |
| JavaScript / TypeScript | 包名、作用域包、package exports、声明文件和部分 CommonJS 导出。 |
| Go | 模块源码和缓存压缩包中的公开声明。 |
| Rust | registry/git 源码中的公开声明与模块。 |
| Java | JAR 内包名与类名；可见性、方法和类型语义交给分析器。 |
| C / C++ | 依赖 include/sysroot 中头文件和可静态识别的声明。 |

- 磁盘缓存由 main 绑定服务器和账号，再按工作区、语言、运行时、依赖 revision 隔离。新查询 revision 同时包含不可变运行时镜像指纹。
- 位置补全键加入当前文档内容摘要，防止同一位置和前缀在导入、类型声明变化后复用旧提示。每个 model/version 只计算一次摘要。
- 库摘要可在小容量缓存中按记录持久化，取消原先 30 MB 硬门槛。关闭磁盘持久化仍可在当前会话按所选策略使用内存摘要。
- 同一工作区、语言、运行时的文件切换和连接恢复保留已验证索引；磁盘索引恢复后重新触发当前补全。
- 临时断线期间只使用当前已验证依赖 revision 的库名称提示；不发送远端补全，不执行缓存 command/edit/resolve。
- 身份、工作区、语言、运行时、依赖 revision 或用户缓存策略改变时重新验证/失效。依赖状态 `mixed`、`unavailable` 不用于库索引。
- 新协调层按目录/模块存储记录，以 LRU 和容量限额回收内存，单次查询、模块数、符号数和磁盘记录仍有上限。旧协议的不可变热索引和有效期保持兼容。
- 应用冷启动且远端完全不可达时，没有当前依赖 revision 的可靠证据，因此不猜测加载其他代次。缓存提示不是安装清单或语义分析结果。

暂不持久化完整项目引用图：引用位置、作用域、跨文件重命名依赖源码和所有相关文件版本。当前缺少整个项目的语义依赖失效协议，直接重放引用图会产生错误跳转或修改。后续如需加入，应先建立文件内容摘要、项目变更版本和 analyzer/toolchain 版本，明确只读结果的失效规则，再评估收益。当前先优化已具备隔离边界的库 API 索引。

学习同时记录明确接受的候选和停顿后稳定出现的手写使用，归一化 `np` 等导入别名，按账号、工作区、语言和接收者隔离，并带衰减与个人回退。重复扫描、删除重输、批量粘贴、注释和字符串不会反复累计。磁盘只保存符号身份、计数和不透明作用域摘要，不保存源码。分析器自定义 completion command 仍受既有服务端策略限制，不作为任意 `workspace/executeCommand` 执行。

## 回归入口

```powershell
npm test
npm run typecheck
npm --prefix client run test:ui:lsp
npm --prefix client run test:ui:ci:core
node scripts/ci/verify-test-routing.mjs
go -C server test ./...
go -C server vet ./...
```

`lsp-tls-ui.spec.js` 在真实 Electron 中使用本地自签证书和实际 `ws`，验证握手、初始化、文档同步、补全、错误指纹/无信任/错误 HTTP 端口拒绝以及更新配置后的恢复；需要 OpenSSL，缺少前置条件必须失败，不能跳过。
`lsp-ui.spec.js` 检查三语言界面、库名称补全、断线本地回退、同 revision 重连不重复下载、磁盘恢复、依赖代次变化失效，以及新查询协议下真实 Monaco 的导入目录和手写学习排序。
Node 测试覆盖凭据发送顺序、连接生命周期、上下文隔离、取消、源码摘要键、不可变索引和有效期。
Go 基线明确验证扫描时间耗尽仍保留已采集模块、整理不绕过步骤限额，以及非 Python 辅助目录不能被当作库根。
新的 hermetic Electron spec 自动进入 CI 的 `core` 分片；`CI Gate` 必须成功。

涉及服务端生命周期、Docker、缓存代次或资源治理时还需相应 Go race/privileged 测试及真实云端验证。仅 mock WebSocket 的 UI 测试或 Node 脚本直接访问服务器，均不能替代 Electron TLS 基线。
